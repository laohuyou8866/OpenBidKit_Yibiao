## 一、功能概览

| 功能 | 客户端页面 | 数据来源 | 服务端存储 |
| --- | --- | --- | --- |
| 插件市场 | `src/features/plugins/pages/PluginsPage.tsx`（379 行） | 经 Main 进程 `pluginService` 走 `https://analytics.agnet.top/plugins` | D1 `openbidkit-resources` + R2 `openbidkit`（插件包另存于 `openbidkit-oss.agnet.top`） |
| 资源下载 | `src/features/resources/pages/ResourcesPage.tsx` | **Renderer 直接 `fetch`** `https://analytics.agnet.top/resources`，不经 IPC | D1 `openbidkit-resources` + R2 `openbidkit`（图片经 `/resource-image` 代理读取） |

关键差异：**插件管理有完整 IPC 链路**（下载→解压→`require()` 执行插件主模块），**资源下载是纯前端直连**，没有 preload/IPC 通道。

## 二、客户端：插件管理

### 2.1 preload 暴露的通道（`electron/preload.cjs` 的 `plugins` 命名空间，13 个）

```
plugins:getAvailablePlugins   获取市场 + 已装插件
plugins:install               安装（从市场下载 zip）
plugins:installOffline        离线安装（本地 zip）
plugins:uninstall             卸载
plugins:enable / disable      启用 / 停用
plugins:update                单个升级
plugins:checkUpdates          检查可升级
plugins:updateAll             全部升级
plugins:openConfig            打开插件配置窗口
plugins:refreshMarket         刷新市场
plugins:clearUpdateFailedState
plugins:notify-event          插件事件回传
```

配置窗口另有两个通道：`plugin-config:get` / `plugin-config:set`（`preload-plugin-config.cjs`，14 行）。

### 2.2 Main 侧文件

| 文件 | 行数 | 职责 |
| --- | --- | --- |
| `electron/services/pluginService.cjs` | 722 | 市场拉取、下载、解压、状态持久化、版本比较、升级 |
| `electron/services/pluginContext.cjs` | 218 | 插件运行上下文与插件窗口 |
| `electron/services/pluginConfigWindow.cjs` | 64 | 插件配置窗口 |
| `electron/ipc/pluginIpc.cjs` | 218 | 上述通道的 IPC 实现 |
| `electron/preload-plugin-config.cjs` | 14 | 配置窗口 preload |

安装流程（`pluginService.installPlugin`）：`fetchAvailablePlugins()` → `downloadPlugin(releaseUrl)`（`https` 直下 + 301/302 重定向）→ `extractPlugin`（AdmZip 解压）→ 校验 `manifest.id` 与市场 ID 一致 → 写入插件目录与状态。插件启用后通过 `require(mainPath)` 直接执行 **主进程代码**，因此插件市场具备与客户端同等的权限。

市场地址常量：`PLUGIN_MARKET_URL = 'https://analytics.agnet.top/plugins'`，下载计数上报 `POST {market}/download`。

### 2.3 菜单与路由接入点（恢复时需同步）

- `src/app/menuConfig.ts`：侧边栏菜单项定义

## 三、客户端：资源下载

- `src/features/resources/pages/ResourcesPage.tsx`
- 端点常量：`RESOURCES_ENDPOINT = 'https://analytics.agnet.top/resources'`
- 支持搜索：`?q=<关键词>`，响应经 `normalizeResource` 归一化后渲染卡片列表，点击卡片弹层展示 `modalContent`（网盘地址等）
- 无 IPC、无 preload 通道；HTTP 层以上完全在 Renderer 内完成
- 菜单接入点与插件管理相同（`navigation.ts` / `menuConfig.ts` / `AppRouter.tsx` / `Sidebar.tsx` / `traffic.js`），埋点中文名为「资源下载」

## 四、服务端（`analytics/worker`）

### 4.1 路由（`src/index.js`）

| 路径 | 处理器 | 权限 |
| --- | --- | --- |
| `GET /plugins` | `handlePublicPlugins` | 公开（`?q=` 搜索） |
| `POST /plugins/download` | `handlePublicPluginDownload` | 公开（下载计数 +1） |
| `GET /resources` | `handlePublicResources` | 公开（`?q=` 搜索，返回带点击量的列表） |
| `GET /resource-image` | `handleResourceImage` | 公开（按 `key` 从 R2 代理图片） |
| `GET/POST/DELETE /api/plugins` | `handleAdminPlugins` | 管理端（`ADMIN_TOKEN`） |
| `POST /api/plugins/sync` | `handleAdminPluginSync` | 管理端 |
| `GET/POST/DELETE /api/resources` | `handleAdminResources` | 管理端（含图片上传） |

### 4.2 存储绑定（`wrangler.jsonc`）

- `RESOURCE_DB` → D1 `openbidkit-resources`（表 `resources`、插件相关表；建表脚本 `analytics/scripts/setup-resource-storage.mjs`）
- `RESOURCE_BUCKET` → R2 `openbidkit`（资源图片 `resources/<id>/<ts>-<rand>.<ext>`）
- 插件包：R2/public 域 `https://openbidkit-oss.agnet.top/plugins/<pluginId>/<pluginId>-v<version>.zip`，staging 前缀 `.staging/`，发布操作有 30 分钟 TTL 的锁与 `plugin-packages` 操作锁

### 4.3 数据字段

**资源（表 `resources`）**：`id, title, tags, description, modal_content, image_key, image_url, sort_order, enabled, created_at, updated_at`
对外响应额外附加：`tagsText`、`analyticsKey`（点击统计键）、`clickCount`

**插件**：`id, name, description, version, previousVersion, author, repository, releaseUrl, previousReleaseUrl, tags, tagsText, iconUrl, downloadCount, sortOrder, enabled, createdAt, updatedAt`

长度上限（`pluginStore.js`）：id 80 / name 120 / description 500 / version 40 / author 120 / repository 300 / releaseUrl 500 / tags 200。

### 4.4 服务端文件

- `src/routes/plugins.js`、`src/routes/resources.js`
- `src/services/pluginStore.js`、`src/services/resourceStore.js`
- `analytics/scripts/setup-resource-storage.mjs`（初始化 D1/R2 资源）

## 六、恢复要点

若要重新启用，需要按顺序恢复四层，缺一层功能即不可用：

1. **服务端**：`src/routes/plugins.js`、`resources.js` 与 `src/services/*Store.js`、`index.js` 路由注册、`wrangler.jsonc` 的 `RESOURCE_DB` / `RESOURCE_BUCKET` 绑定
2. **数据**：D1 表与 R2 对象（插件包文件已不在仓库内，需重新上传；条目内容见数据存档文件）
3. **客户端 Main**：`pluginService.cjs` / `pluginContext.cjs` / `pluginConfigWindow.cjs` / `pluginIpc.cjs` / `preload-plugin-config.cjs` 与 `preload.cjs`、`ipc/index.cjs` 的装配
4. **客户端 Renderer**：两个页面 + `navigation.ts` / `menuConfig.ts` / `AppRouter.tsx` / `Sidebar.tsx` / `ipc.ts` / `traffic.js` 接入点

安全提示：插件机制会在用户机器上以主进程权限执行第三方代码，恢复前应补充包签名或哈希校验。
